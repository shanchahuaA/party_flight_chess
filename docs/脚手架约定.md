## 常用命令（agent 高频，开工先看这）

| 包 | 命令 | 说明 |
|---|---|---|
| kernel | `npm run typecheck` | `tsc --noEmit`（**CI 不查内核类型**——CI test job 只跑 vitest；提交前必须自查这步） |
| kernel | `npm test` | vitest 全量 |
| kernel | `npx vitest run test/xxx.test.ts` | 单文件 |
| kernel | `npm run probe` | 常驻探针 REPL（`test/probe.debug.test.ts`；全量测试自动跳过；`-t "节名"` 聚焦） |
| kernel | `npm run dump:board` | 打印棋盘全表（格 id/型/生态/街/坐标/邻接） |
| client | `npm run typecheck` | `vue-tsc --noEmit` |
| client | `npm run build` | 构建自带类型检查 |

- 跑命令一律 `cd <绝对路径> && cmd` 单调用（别赌 shell 的 cwd 记忆）。
- 沙箱内 npm 一律带 `--cache /tmp/npmcache`——默认缓存目录 `C:\NodeJS\node_cache` 被沙箱拦，不带则首调必炸（权限错误），别等炸了再想。
- 内核 TS lib=**ES2022**：`findLast` 不可用（用 `[...arr].reverse().find`）、无 DOM 类型（连 `console`/`process` 都要文件内 declare）。
- 浏览器冒烟与调试通道：见 [agents/dev-channels.md](./agents/dev-channels.md)、[agents/iab-smoke.md](./agents/iab-smoke.md)。

## RNG 与测试确定性（T1..T8a2 回顾定案）

- 内核**五条命名流**（`kernel/src/rng.ts`）：`setup` 开局分发／`deck` 事件牌堆／`items` 道具牌堆／`dice` 走格骰+检定（含年兽伤害骰）／`world` 世界恶意+野狗+机器人日程。**新增随机消费点必须显式归流**（`draw(stream)` 流参数必填）——新消费点只位移自己那条流，改牌池不再炸走格测试。
- 搜种子**只吞 `KernelError`**（业务拒绝=换种子），其余异常原样抛——内核真缺陷不许伪装成「没搜到种子」（T8a1 教训）；搜索约束读**结构化事实**（`cardDrawn` 等），禁解析战报中文文案（文案会改，事实是协议——`kernel/test/helpers.ts` 顶部有全文）。
- 数量断言两类：全池守恒类一律从 `M1_EVENT_POOL`/`M1_ITEM_POOL`/`ITEM_CARDS` 派生；表一/表二张数与分布的**对表契约**（21/20、choice 14/self 11）只允许住在「对表」describe 里——那是跟数值表对账的刻意钉子，别处不许再写魔法数。

## 状态机类票自检三问（提交前各有一条测试或明确豁免）

窗口/挂账/名册类机制动笔前自问：

1. **同一实体被两个来源并发操作**会怎样？（同格多头死狗复打双份战利品——T6b 教训）
2. **挂账期间标的消失**会怎样？（海关挂账的仅剩卡被转走→收窗崩 tick——T7 教训）
3. **边界 tick 重入**会怎样？（全员确认恰落窗截止 tick→一 tick 双吞世界回合——T8a1 教训，回归测试在 window.test）

## 端口与本地开发

- `client`：`vite dev`，端口 **5173**，热更新。
- `server`：`wrangler dev`，端口 **8787**，本地模拟 DO（本地 SQLite 态）。
- vite 把 `/ws` 代理到 `ws://localhost:8787`——前端代码只写相对路径，感知不到双进程。

## 协议纪律

- 全部 WS 消息是 `shared/protocol.ts` 里的 discriminated union（`type` 字段判别），client/server 禁止各自手写消息类型。
- 上行 = 意图（掷骰、打卡、出道具卡、抉择选择、确认结束）；下行 = 事实（状态变更、回合号 + 截止时间戳）。演出（逐格动画、秒数）客户端本地播。
- 所有上行消息带 `turn`（客户端已知的回合号），DO 校验后才生效——防过期操作。

## CI / 部署

单个 GitHub Actions workflow（`deploy.yml`）三个 job：

1. **test**：kernel 规则内核单测（vitest；#17 起的首个测试集）。
2. **pages**：构建 client（`vue-tsc + vite build`）→ `actions/upload-pages-artifact@v3` + `actions/deploy-pages@v4` 发 GitHub Pages。
3. **worker**：`cloudflare/wrangler-action@v3` 部署 Worker/DO。仓库 Secrets：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。

`wrangler.jsonc` 要点：`migrations: [{ new_sqlite_classes: ["Room"] }]`（免费层 DO 必须 SQLite 后端）；Worker 绑自有域名 custom domain。若 Pages 侧遇阻，可退到「Worker 静态资产单域名全包」方案（同样免费），部署任务实施时权衡。
