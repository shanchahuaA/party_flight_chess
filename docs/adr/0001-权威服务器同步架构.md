# 权威服务器同步架构（Cloudflare Worker + Durable Object）

状态：accepted（2026-10-07）

## 背景

2–8 人手机浏览器派对局，玩家边聊边玩、随手锁屏。研究确认两条硬事实（详见研究票「联机架构研究：免费后端能否承载世界回合同步」「手机浏览器环境事实核查」）：

1. 手机浏览器切后台/锁屏后 JS 完全暂停（iOS）或强节流（Android），WebSocket 必断且 `onclose` 不可靠——**任何游戏逻辑放在任何一台玩家手机上都不可信**。
2. Cloudflare 免费层 Durable Object（仅 SQLite 后端）+ WebSocket Hibernation + Alarm 可承载朋友局负载（约 2,170 计费请求/局 @1s tick，对照 100,000 请求/天；事件驱动 + 休眠后实际远低于此口径）。

## 决策

**每个房间 = 一个 Durable Object，它是本局唯一权威。**

1. **状态权威**：座位、手牌、棋子位置、血量、回合号、回合截止时间戳全部存在 DO 内（SQLite 存储），客户端本地状态只是缓存。
2. **连接**：WebSocket Hibernation API；心跳用 `setWebSocketAutoResponse()`（官方明示不计费、不唤醒进程）。客户端约 25–30 秒收不到任何消息即进入「重连中」，不依赖 `onclose` 感知断线。
3. **世界回合推进只由 DO 判定**：Alarm 到点强制推进（未操作者由自动掷骰代打）；全员确认结束则提前推进（玩家操作唤醒 DO）。客户端永不推进回合，本地定时器只渲染秒数。
4. **协议原则**：上行只有「意图」（掷骰、打卡、出道具卡、抉择选择、确认结束），DO 校验回合号与合法性后广播「事实」（状态变更 + 新截止时间戳）。演出（逐格移动动画、倒计时秒数）由客户端本地插值播放——协议中不存在"每走一格"或"每过一秒"的消息。
5. **计时**：服务端 epoch 截止时间戳是唯一权威。客户端建连时对时（多次采样取最低 RTT 算偏移），用 `performance.now()` 单调插值维护 `serverNow`；回前台、重连、`pageshow(persisted)` 时幂等地重新对时 + 全量拉房间快照覆盖本地，**绝不补算锁屏期间发生的事**。
6. **房间生命周期**：
   - 身份 = 进房时服务端签发的 token，存 localStorage；刷新/重连凭 token 找回座位，不重输昵称。
   - 玩家掉线/退出：棋子转「自动掷骰」接管、抉择卡按默认项代选（与超时同路径），随时可重连归队——「任意玩家消失几分钟再回来」是正常流程，不是异常。
   - 全员离线 5 分钟后 DO 自毁（房间即世界，零持久化）。
   - **房主** = 创建者持有的权限标记，不影响游戏权威运行。特权四项：开局配置（计时模式、休息开关与时长）、按下开始、解散房间、踢人。房主主动退出或离线超 5 分钟，权限自动转给最早加入的在座玩家；被踢玩家的 token 拉黑至房间销毁，其棋子转自动掷骰。

## 否决的备选

- **房主客户端权威**：省一个后端，但房主一锁屏全场冻结——派对场景必然发生，不可接受。
- **P2P WebRTC（手动信令）**：无权威裁决方、NAT 打洞在 4G/公司网络必失败一批、信令复杂度不比 DO 低。仅作为 Cloudflare DO 完全不可用时的兜底（备选还有 LeanCloud Play，20 CCU 免费额度）。

## 后果

- 本地开发双进程（vite dev + wrangler dev）；DO 单线程串行既是额度上限，也是并发模型简单性的来源。
- `*.workers.dev` 在大陆被 DNS 污染，Worker 必须绑自有域名（购买动作是部署链路任务的人工前置）。
- 免费层为硬上限：朋友局余量充足，若将来公开运营需重估。
