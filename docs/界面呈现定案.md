# 界面呈现定案（页面地图 · 游戏页布局 · 战报）

> 来源：[世界消息呈现定案（事件播报不打断操作） #11](https://github.com/shanchahuaA/party_flight_chess/issues/11) 拷问定案，承接 [世界回合手感原型 #7](https://github.com/shanchahuaA/party_flight_chess/issues/7) 三轮体感结论（播报不打断操作、掷完立刻逐格走、回合间休息）。修订 [玩家对抗与交互机制定案 #10](https://github.com/shanchahuaA/party_flight_chess/issues/10) 的观战弹幕条款。全部条目已于 2026-10-08 经配套原型手机实玩裁决回收（原「⚠️ 待原型」标记均已回填定案结论），可直接进实现。

## 一、页面地图（4 页 + 弹窗原则）

| 页面 | 职责 | 备注 |
|------|------|------|
| **进房页** | 输房间码/点链接 → 昵称 → 进大厅 | 链接直跳本页自动填码 |
| **大厅页** | 角色明选、暗牌抽 2 选 1、房主配置面板（弹窗）、开始按钮 | 非房主见只读配置预览 |
| **游戏页** | 满屏棋盘 ＋ 底部 dock ＋ 战报叠加 ＋ HUD ＋ 设置齿轮/帮助按钮 | 主页面，占绝对时长 |
| **结算页** | 亮暗牌、称号、积分排名、找战犯数据、群体失败章、「再来一局（可改配置）」 | 最后一波插在游戏页最后、进入本页之前（形态 UI 归棋盘与世界恶意原型票） |

**弹窗原则**：四大页面之间才用页面导航；页内一切辅助信息（设置、帮助、暗牌目标、角色被动、卡面详情、战报全屏展开）一律**浮层弹窗**，禁止为查看类操作切换页面——避免切页丢状态、数据重拉。本条款是硬规格，实现票不得用路由跳转替代弹窗。

**局间配置**：玩完一局进入结算页后，房主可再改全套开局配置（局长、血量、世界回合窗、计时模式、休息时长）开下一局；**局中数值一律冻结**（结算制下中途改参数破坏公平，MVP 不做局中调参），局中设置面板只含展示类开关（音效/震动）。

## 二、游戏页布局

**棋盘满屏**：环形棋盘占满整个手机视口，如竖屏手游——不再用「状态条+棋盘+手牌」纵向堆叠的文档式布局（#7 原型那种挤法已否）。

**底部 dock**（固定区，悬浮于棋盘下沿）：

- **固定钮**：中央大圆钮「🎲 掷骰」＋ 长条「✔ 确认结束」。
- **情境任务槽**：其余一切情境操作以「任务条」出现在 dock 上方，一次最多两三条、做完消失、多任务排队。抉择卡=任务条（点开卡面）；警长查货窗=任务条组（报备/转让/查验按可用性点亮）；道具卡选目标=点手牌卡后在棋盘上选目标头像。设计原则：任何新机制（赌狗时刻、最后一波）都是「又一个任务槽」，不得重排布局。
- **手牌横滑**：dock 上方一排可横滑的缩略小卡，点开半屏抽屉看大卡/打牌/选目标。
- 实玩通过：固定钮+任务槽+手牌横滑**点得过来**，布局可进实现。
- **实玩修正（硬规格）**：**掷骰与确认结束分离**。掷骰完成后**不自动确认**，玩家仍可打道具卡、做任务槽操作，直到自己点「✔ 确认结束」才进等待区（与事件卡定案 1.3「确认之前任意时刻可打道具」一致）。stub 首版把掷骰即视为确认，实玩反馈后已修正——实现票不得重犯：确认前不能锁操作，确认后才锁。超时未掷/未确认由系统替掷并自动确认（超时替掷语义不变）。

**HUD（四角压缩）**：

- 自己的血量：头像旁心形数字/微条。
- 回合进度与倒计时：`回合 5/15 · ⏳ 18s`；休息时变 `⏸ 休息 8s ·[跳过]`。
- 暗牌目标图标：点开弹窗看自己的目标（不放设置里）。
- 其他玩家的血量：棋子旁微型血条（满屏棋盘是全局视角，必须随时看到所有人血量）。
- 积分：**局中不显示**（结算屏负责，避免剧透排名）。
- 实玩通过：四角压缩分布不遮棋盘关键区；顶部「回合 pill ＋ 🎯暗牌/📖帮助/⚙️设置」可容。
- 实玩修正：遮挡感的来源是**战报 V1 叠加**盖棋盘下缘（用户点名「v1 有点遮」），并非 HUD 本身——定 V2 让位带后此问题消解；HUD 保持四角方案。

## 三、战报（世界消息的载体）

**架构定案：让位带（V2）＋全量抽屉**（2026-10-08 手机实玩裁决）。战报以**顶部让位带**常驻：棋盘顶部让出一条流水带，新消息推入、旧行下移让位；点带内任一条目展开**全屏战报抽屉**（上滑翻全局、回合分节线、点条目看 flavor，再点收起）。棋盘本体仍接近满屏，只让一个窄条，不采用左下角叠加（V1 因为遮棋盘下缘格子被否）。

**原型裁决记录（同屏切换三变体实玩对比）**：

- **V2 让位带 = 定案**。白底圆角条浮在棋盘顶缘，最新 1–2 条常驻、其余全部进抽屉；**条目可点开全量抽屉看详情**——这是实玩发现 V2 首版缺「点开详情」后补定的规格，实现票必须带此入口。
- **V1 叠加流水 = 留档**。左下半透明流水区（最新 3–4 条，10s 无新消息淡出至低透明度——淡出时机实玩确认合适）。被否原因：手机上盖住棋盘下缘格子。若日后为平板/横屏布局启用，实玩验明背景透明度需降到约 .6 以下（首版 .78 太实）。
- **V3 pill 抽屉 = 留档**。常驻仅一枚最新消息 pill（角标计未读），战报主体全靠抽屉。

**条目结构**（一行式，已定案）：

- 字段顺序：`类型图标 · 谁 · 卡名/效果名 · 结果短语`。例：`🃏 小红 抽到「脚滑」→ 回退 2`；`⚠️ 小蓝 踩中扣血陷阱 → −1 💔`；`🎁 小王 打出「弹弓」→ 小灰回退 2`。
- 类型图标与淡色底：🃏 事件 ／ ⚠️ 陷阱 ／ 🎁 道具 ／ 🌲 世界恶意 ／ 📣 系统·结算播报 ／ 📜 回合小结。
- 卡面场景文案（叙事皮 flavor）不进一行，在战报抽屉里**点条目展开**看全文。

**回合小结**：一类消息条目（`📜` 开头），插进战报流顶部，同时是战报抽屉里的**回合分节线**。只汇总本回合已播报的关键结果为一行（扣血/回退/入袋/罚停），不做全区块复盘。

**保留与弱化**（已定案）：

- 存储：客户端全量保存整局消息，无上限（一局几百条量级）。
- 渲染：战报抽屉只渲染最近约 50 条，上滑增量渲染更早条目。
- 弱化：仅「新条目短暂高亮约 2 秒渐出」；**不做**旧条目透明度/灰化——时间轴的实感优先，分节越实越好翻。

**消息即日志（数据结构草案，影响后端）**：

```ts
type MessageKind = 'event' | 'trap' | 'item' | 'malice' | 'system' | 'summary' | 'score';

interface MessageEntry {
  id: string;            // 全局递增序号
  turn: number;          // 世界回合号（分节线依据）
  kind: MessageKind;
  who?: string;          // 主语玩家 id（触发者/使用者）
  targets?: string[];    // 被指认目标 id（联动高亮数据源）
  cardRef?: { pool: 'event' | 'item'; id: string; option?: number }; // 点开回看卡面
  text: string;          // 一行结果短语
  flavor?: string;       // 叙事皮文案（点开才看）
  emphasis?: 'normal' | 'highlight' | 'target' | 'big';
  // big = 最后一波/全局性大事：战报置顶全宽条（细节归棋盘与世界恶意原型票）
}
```

实现约束：Durable Object 以 **append-only 消息流**广播（世界回合窗内实时 append + 休息期集中 append）；**快照恢复必须带全量消息**（掉线重连后战报完整，不重播动画）；结算页的找战犯数据直接从消息流聚合，可点溯源跳到对应条目。数值表票的「积分分项透明播报」即 `score` 类条目。

## 四、播报与棋盘联动（全联动，已定案）

任何世界消息播报，棋盘同步给**三级视觉信号**：

| 级别 | 触发 | 表现 |
|------|------|------|
| 描边脉冲 | 普通事件/陷阱/道具/恶意落地 | 触发者棋子描边高亮约 1 秒 |
| 目标脉冲 | 指认型效果（弹弓/脚镣/惊雷/系统指认） | **目标**棋子红色脉冲，比描边重一级 |
| 格角标 | 场地型道具（香蕉皮） | 附着格画皮角标，直到被触发 |

- 死亡/罚停走既有棋盘语言：棋子变暗/加锁标。
- 实玩定案：**描边脉冲**（S1）。触发者棋子发光描边约 1 秒的手感比光圈跳动清晰且不糊棋盘；目标红脉冲、场地格角标按上表。光圈样式（S2）在 stub 中留档对比，不采用。

## 八、待原型裁决清单（已全部裁决回收）

本票配套 stub（满屏棋盘 + 变体切换器）手机实玩后逐项回收：

1. 战报三形态 → **V2 让位带**（见第三节裁决记录）；
2. 联动两样式 → **描边脉冲**（S1）；
3. 抉择卡两形态 → **中央卡牌浮层**（K2）；
4. dock + 任务槽 + 手牌 → 点得过来；实玩发现**掷骰后自动确认**违背事件卡定案 1.3，规格修正为掷骰/确认分离（见第二节硬规格）；
5. HUD → 四角不遮棋盘，遮挡感来自 V1 战报，随形态定案消解；
6. 淡出时机 → 10s 合适。

实玩带来的规格增补（实现票注意事项）：

- V2 让位带条目**必须**可点开全量战报抽屉（详情入口不能缺）。
- 播报条目的主语以 `who` 字段统一渲染（图标 · 谁 · 文本 · 效果），消息文本里不重复写玩家名——stub 首版两处都写导致「小黄 小黄」重复，已修正。
- 消息数据保持结构化（`MessageEntry`），客户端根据 `who`/`targets`/`emphasis` 自行渲染联动，不靠文案解析。
