## 零、这条票定下的四件事

1. **验收基线从「4 人」改为「2 台真机」**。2 人 + 6 假人凑满 8 座，47 条界面验收线**全部可验**（逐条对账见附录 A）。真正需要 ≥3 人的只有手感/社交面，单列在 §五，M3 关票时记「未验」不记「通过」。
2. **只跑压力配置**，默认配置不必跑完全程。默认配置下的单局时长基线不再作为验收项，改用「每窗实际耗时」这个与配置无关的指标（§三 3.1）代替。
3. **联机只走万维网**，不做本地局域网起服。正式场统一走「一人开热点、全场连热点」——大家借蜂窝出口出去，访问的仍是同一个 sync 域，与各自联网等价，但把「场地 WiFi 是否被运营商过滤」这个变量整体消掉。
4. **新增一件实现物：客户端记录器**（[#51](https://github.com/shanchahuaA/party_flight_chess/issues/51)）。手机上没有控制台，操作流程/耗时/卡点/替掷比例/掉线恢复这些只能靠客户端自己记，人工抄不动。

## 一、测试组织

### 1.1 人、设备、网络

| 项 | 定案 |
|---|---|
| 人数 | **2 台真机为基线**——可约 2 位朋友，也可你一人持两台设备（脚本记录不需要第二个人配合） |
| 设备 | **≥1 台 iOS + ≥1 台 Android**，一律用**系统浏览器**（Safari / Chrome） |
| 微信内置浏览器 | 只做「能否打开」的附带记录，**不作验收面**（MVP 口径本就是「能玩即达标」） |
| 正式场网络 | **全场连你手机的热点**（统一出口） |
| 预演场网络 | **一台流量 + 一台场地 WiFi**——目的是产出「家宽线路现在还滤不滤」的实测证据给 [#12](https://github.com/shanchahuaA/party_flight_chess/issues/12) |
| 入口 | `https://sync.99966688.xyz`（联机必须走 sync 域；GitHub Pages 上 WS 走同域相对路径会 404，只可单机） |

**网络阶梯（写死，不现场排查）**：

```
L0  各自网络    → 开场 5 分钟探活
L1  全场热点    → L0 任一打不开即改热点，记下现象继续
L2  单机退化    → 热点仍不行 → 只验界面完全体（该场不算联机验收）
```

规则：**任一台打不开就换，不排查**。线路问题当场修不了，排查 30 分钟=毁掉整场。

```
5. 顺手确认：入席者不再能掷骰（提示「不再行动」而非「已掷过骰」），但仍能打整蛊卡
```

## 二、测试操作单

> 每条都是「怎么做 → 应见什么」。**应见什么**照 [M3界面完全体验收清单](M3界面完全体验收清单.md) 的条目号引用，本文件不重复其正文。
> 机器记录自动对齐，不需要人抄；人只记 §三 3.2 那六件。

### A 场：压力局（正式验收主战场）

**压力配置（全部落在可调域内，无需改码；域校验见 `kernel/src/game.ts:77-83`）**

| 旋钮 | 值 | 理由 |
|---|---|---|
| 局长 turnCap | **8** | 短局快进到终局年兽战，8 回合 × 15s ≈ 2 分钟进最后一波 |
| 世界回合窗 windowMs | **15s** | 10s 会让全员吃替掷（那就只测到替掷，测不到 UI）；15s 是「紧张但不失控」 |
| 回合间休息 restMs | **5s** | 0s 会抹掉战报阅读窗口，而战报可读性是本轮重点 |
| 恶意周期 maliceEvery | **2** | 最密，8 回合撞 4 波，四型覆盖概率最高 |
| 恶意强度 maliceLevel | **猛（fierce）** | 伤害翻倍，血量压力真实 |
| 血量 maxHp | 10（默认不动） | — |
| 计时模式 | 世界·即时（默认不动） | — |
| 人数 | **2 真人 + 6 假人 = 8 座** | 顺带压测 8 人局布局（吸底 / 拥挤 / 任务槽压栈） |

> ⚠️ **两处已知覆盖空缺**（不必现场补救，记一行就行）：
> ① **通关席不会出现**（8 回合均值 44 步 ≪ 净步 90）→ 已由 P-2 单机自查覆盖。
> ② **海关窗 / 野狗 / 特定恶意型靠抽卡与随机**，短局可能抽不到 → 记「本场未触发」，B 场或后续局补。

#### AS-1 网络与进房（≈3 min）

1. A 机（iOS）开**个人热点**；B 机（Android）连这个热点。
2. A 机浏览器打开 `https://sync.99966688.xyz/?rec=1&dev=1` → 创建房间 → 记下 5 位房号。
3. A 机点「复制邀请链接」（`copyInvite`，`client/src/net/roomStore.ts:434`），把链接发给 B 机。
4. B 机打开该链接 → 输昵称 → 进大厅。

**应见**：L-01 进房表单 · L-02 链接直达 · L-04 座位列（两台互见、均在线、A 有皇冠）。
**探针**：`__pzroom().ws === "open"` 且 `phase === "lobby"`。

#### AS-2 配置与凑局（≈3 min，A 机操作）

1. 房主打开配置面板，按上表设：局长 8 / 窗 15s / 休息 5s / 恶意周期 2 / 恶意强度 猛。
2. 加假人 ×6（假人钮，`MAX_BOTS = 7`，`shared/protocol.ts:23`）→ 满 8 座。
3. 顺带改一项再改回来，看 B 机是否同步。

**应见**：L-07 配置面板（B 侧摘要 1s 内同步、非房主只读）· L-08 开局闸（<2 人时禁用）。

#### AS-3 选角、开局、抽暗牌（≈2 min）

1. 两人**各选不同角色**——建议 A 选「皮糙肉厚」（免疫第一次扣血）、B 选「轻装上阵」（穿戴负面减半 + 开局手牌 +1），让两条被动都有机会显形。
2. A 机点「开始」→ 全员弹暗牌 2 选 1 → 各自选完进游戏页。

**应见**：L-06 明选角色（互见、可看详情浮层）· L-09 抽暗牌 · G-02 暗牌入口。

#### AS-4 第一回合（第一个世界回合）

**本局第一窗必然触发新手引导**（前提：设备未做过，清过 localStorage）。

**应见**：G-05 首次引导（3 步，可跳过）· G-13 掷骰/确认分离（掷完不锁 dock）。
**观察**：15s 够不够点完「打牌 → 掷骰 → 落格 → 确认」——记录器会给出本窗实际耗时。

#### AS-5 八个世界回合（≈3–5 min）

正常玩，不必刻意触发。每 2 个世界回合来一波恶意（turn 2/4/6/8，共 **4 波**）。

**应见**：G-10 描边脉冲 · G-11 目标红脉冲 · G-12 罚停加锁标 · G-16 任务槽（环岛选路 / 扶择卡 / 选目标）。
**观察**：四人血量曲线（猛档 + 4 波恶意 + 陷阱，血量压力是否过大）· 战报能否跟上 · 有无替掷。
**机器自动记**：每窗实际耗时、`auto:true` 的替掷/代选次数、`error` 拒因。

#### AS-6 最后一波（≈1 min）

第八窗收口即触发终局。**年兽 145 血**（`25 + 15 × 8`，`kernel/src/game.ts:125-126`）；8 人 × 1d12 均值 6.5 ≈ 52/波 → **预期 3 波收束**。

**应见**：🐉 砍击钮、战况条（波数 + 兽血）、爆 12 高亮、反噬行（猛档 −2）、安慰奖发卡。
**⚠️ 已知风险**：猛档下反噬 −2/波 + 4 波恶意，**很可能以「群体失败」收束**。群体失败也是合法验收结果（S-03 盖章 + 全员作废 + 找战犯），但「胜利 sting」就验不到——若本场群体失败，**B 场补一局温和胜利局**（BS-6）。

#### AS-7 结算（≈3 min）

**应见**：S-02 五项分项与排名 · S-03 称号与暗牌亮牌 · S-04 找战犯溯源（点证据跳战报闪光）· **S-05 动作区吸底（8 人局正好压测）**。
**动手核**：挑一人，把他的五项分项按 [内容数值表 §5.1](内容数值表.md) 口算一遍，与页面对账（进度 = `max(0, ⌊净步/10⌋)` / 存活 4 / 称号 8×条 / 整蛊 2×次 / 通关 10/8/6）。

#### AS-8 局间（≈3 min）

1. 结算页停住别点 —— 先确认它**不闪走**（S-01）。
2. 房主点 ⚙ 改配置：恶意强度改 **温和**、局长改 **6**。
3. 房主「🎴 开下一局」→ 全员抽暗牌 → 进新局。
4. 再点「🏠 回大厅」看 S-08。

**应见**：S-01 结算页停留 · S-06 房主局间改配置 · S-08 回大厅。

**A 场合计 ≈ 18–22 分钟**（含摸索与笑声，不含复盘）。

### B 场：专项补测

B 场分两类：**视 A 场结果决定是否要跑**（BS-1/BS-2/BS-6），和**必须专项触发的**（BS-3/BS-4/BS-5）。

#### BS-1 淘汰观战（仅当 A 场无人出局时跑）

猛档 8 回合有人血尽是最可能的，但若全员活着：

1. 继续用压力配置开一局（恶意强度保持猛、局长拉到 10）。
2. 等任意一人血尽出局（或两人轮流挨打）。

**应见**：G-06 观战横幅（`☠ 观战中` + **dock 整块消失**、手牌消失，🎯/📖/⚙ 仍可用）· G-18/A-07 出局音效只在本人机上响。

#### BS-2 海关窗（仅当 A 场未抽到「黑市开张」时跑）

「黑市开张」是事件池 21 张里的 1 张（`kernel/src/data/events.ts`），单池洗匀，8 回合短局有概率抽不到。

1. 开一局（局长 8、窗 20s 放宽），让真人多踩事件格。
2. 抽到即变海关风云。

**应见**：G-16 任务槽（报备转让三步表 / 查验清单 / 交卡表 + 倒计时）· 警长 15s 不查即退化为自由转让且不阻塞。
**观察**：15s 查验钟对慢手玩家是否太紧（`CUSTOMS_CHECK_MS`，`kernel/src/game.ts:116`）。

#### BS-3 中局踢人（必做，≈5 min）

1. 开一局（任意配置），等进入游戏页。
2. **A 机**（房主）点 ⚙ → 成员管理 → 对 B 点「请出」。
3. **应见**：二次确认浮层（G-07：「请出 阿强？他将失去本局，且无法再进本房间」/ 确认 / 取消）——先点**取消**，确认没踢。
4. 再点一次 → **确认**。
5. **应见（B 机）**：被请出提示 → 回首页；**应见（A 机）**：该座位标已请出，棋子转自动掷骰，局面继续推进。
6. **B 机重进本房**（用原邀请链接）→ **应见**：403 拒（token 拉黑至房间销毁）。
7. 顺手看：假人行**没有**「请出」钮；非房主看不到成员管理。

#### BS-4 锁屏 2 分钟恢复（必做，≈4 min）

1. 任意对局进行中，**B 机**按电源键锁屏，**静置 2 分钟**（真机真锁，不是切页签）。
2. 解锁回前台。

**应见**：T-03 横幅三态正常过渡 → 状态与战报完整、无补播动画、不重复结算。
**探针**：`__pztime().samplesN > 0`（重新采样阵已建）· `__pzroom().banner === null` · `__pz().turn` 与锁屏前连续不倒退。
**观察**：2 分钟内这局有没有因为超时替掷而跑掉一大截（记录器比对锁屏前后 `turn`）。

#### BS-5 断线归队（必做，≈4 min）

1. **B 机**开飞行模式（或关 WiFi + 蜂窝）**10 秒**，再恢复。
2. 若未自动恢复，看横幅是否给出手动重连钮。

**应见**：T-03 断线重连（「连接断开，自动重连中…」→ 恢复后 toast「已重新归队」）。
**探针**：`__pzroom().silentMs` 峰值 · `ws` 状态迁移 · 恢复后 `mySeat` 不变。
**加测**：**A 机**同时关网 30 秒，验证「全员离线」不会销毁房间（销毁线是 5 分钟，`server/src/room.ts:80`）。

#### BS-6 胜利局（仅当 A 场以群体失败收束时跑）

1. 开一局：局长 6 / 恶意强度 **关（off）** / 窗 20s。
2. 打到年兽被砍死。

**应见**：胜利 sting（`win.mp3`，人群欢呼）· 登顶名次 · 「年兽被击杀」战报行。
**顺带**：T-02 战报不截断——锁屏 2 分钟后开全量抽屉，**能翻到本局第一条**。

#### BS-7 极端节奏压测（必做，≈3 min）

1. 开一局：窗 **10s** / 休息 **0s** / 局长 5 / 恶意温和。
2. 两人**故意全程挂机**，什么都不点。

**应见**：G-14 超时替掷连跑 5 个世界回合——替掷 + 自动确认全程不卡、不重复、不开空窗；终局年兽战照样收束到结算页。
**观察**：这是「最坏情况」压测，看的是**不阻塞**，不是好玩。

**B 场合计 ≈ 20–30 分钟**（跑满的话）。

## 三、观察记录表

### 3.1 机器记录（记录器，[#51](https://github.com/shanchahuaA/party_flight_chess/issues/51)）

> **零定时器**：只在下行消息到达时落一条。每条同时记 `Date.now()` 与 `serverNow()`——两台手机的墙钟可能差几十秒，跨设备对齐只能靠 `serverNow`（来自既有对时 `ServerClock`，`client/src/net/roomStore.ts:711`）。

| 记录项 | 数据来源 | 判读什么 |
|---|---|---|
| 每窗实际耗时 | `windowStart` 到达 → `windowEnd` 到达 | **核心节奏指标**（与配置无关，可跨局比较） |
| 全员点完多快 | `windowStart` → 最后一条 `confirm` | 窗长够不够的最直接证据 |
| 卡点 | 窗内相邻两条事实的最大间隔 vs `windowMs` | 超 2 倍窗长自动标红，不用人记 |
| 替掷 / 替确认 / 代选次数 | `roll{auto:true}`、`confirm{auto:true}`、`cardResolved{auto:true}`、`routeChosen{auto:true}` | **「看不懂 / 来不及」的客观代理** |
| 误操作 | `error` 下行全部原样记录 | **误操作的客观代理**（点了不允许的） |

## 五、需 ≥3 人的项（本场跳过，M3 关票记「未验」）

> **先纠一个我上一轮的估高**：逐条对账后，**47 条界面验收线 100% 可 2 台真机验**（见附录 A）。真正需要 ≥3 人的不是清单条目，而是**手感与社交面**——这类东西假人替不了。

| # | 项 | 为什么 2 台测不出 |

| M-1 | 世界·即时「全员同时行动」的**拥挤感** | 2 人没有「挤」的感觉；6 个假人不会犹豫、不会喊 |

### 真聚会当天怎么补（5 分钟速查）

## 六、验收口径：「一局无阻塞完成」的精确定义

### 6.1 必过（任一不过 = 当天验收不通过）

| # | 条件 |
|---|---|

文案费解但能猜 · 音效不响 · 动效缺失 · 视觉挤压错位 · 假人行为怪 · 非关键按钮不顺手 · 单条 toast 没看清 · 通关席本场未触发 · 海关窗/特定恶意型本场未抽到（记「未触发」）。

### 6.3 一票否决

- 某人被卡 ≥2 分钟且只能靠刷页 / 重开房救
- 结算分数算错
- 某回合不推进（全员确认后不开下一窗）
- 房间无故销毁或全员掉线不归队

### B.9 一局时长的构成（估算公式）

```
常规段（世界·即时，无人提前确认）
  = turnCap × windowMs + (turnCap − 1) × restMs
  默认 15×30s + 14×10s = 590s ≈ 9 分 50 秒
  压力 8×15s + 7×5s   = 155s ≈ 2 分 35 秒

最后一波段
  = ceil( (25 + 15n) / (n × 6.5) ) × windowMs
  8 人：145 / 52 = 2.8 → 3 波 = 45s
  默认 4 人：85 / 26 = 3.3 → 3–4 波 = 90–120s

轮班·限时（最坏值，实际远小）
  = turnCap × 行动人数 × windowMs + (turnCap − 1) × restMs
```

> 实际时长都短于公式值：全员确认即提前收窗（`kernel/src/game.ts:1503-1505`）、休息可跳过（`kernel/src/game.ts:444-448`）。
